# راهنمای نسخه‌بندی OWP

OWP از [Semantic Versioning 2.0.0](https://semver.org/) با قالب MAJOR.MINOR.PATCH استفاده می‌کند. قرارداد نسخه‌دار آن شامل Core، رفتار Skill، ساختار Profile و رابط بین عامل‌هاست.

| مثال | کاربرد | نوع |
| ---: | ---: | ---: |
| 2.0.0 | تغییر ناسازگار مسئولیت‌ها، ساختار یا قواعد الزامی | MAJOR |
| 1.1.0 | افزودن قابلیت یا قاعده سازگار با نسخه قبل | MINOR |
| 1.0.1 | رفع ابهام، خطا یا اصلاح مستندات بدون تغییر قرارداد | PATCH |

## فرایند انتشار

۱. تغییر پیشنهادی را با دلیل و اثر آن در Issue یا PR توضیح بده.
۲. Core را مرجع نگه دار؛ Skill و Profile را فقط به اندازه لازم همگام کن.
۳. نسخه در VERSION، عنوان و متادیتای Core و Skill، قالب و راهنمای فارسی را یکسان کن. لینک‌ها و ارجاع‌های نسبی Skill، نبود اطلاعات خصوصی و عدم تضاد قواعد را بررسی کن.
۴. CHANGELOG را با تاریخ و تغییرات نسخه تکمیل کن.
۵. پس از بازبینی، نسخه را روی main تثبیت کن. با مجوز مالک، Tag به شکل vMAJOR.MINOR.PATCH و Release متناظر ایجاد کن. Tag را روی Commit دقیق نسخه قرار بده و نسخه منتشرشده را بازنویسی نکن.
۶. در صورت ارائه فایل ZIP، آن را از همان Tag بساز؛ بسته Skill باید پوشه کامل operation-workflow را حفظ کند.

## استفاده و ارتقا در پروژه‌ها

نسخه مورد استفاده را در Profile ثبت کن. برای ارتقا، CHANGELOG و تغییرات Core را بررسی کن و ناسازگاری‌ها را با قواعد اختصاصی پروژه بسنج. سپس نسخه Core، Skill و منابع همراه را همزمان جایگزین کن. تغییرات اختصاصی پروژه دلیل ایجاد نسخه جدید OWP عمومی نیستند. به‌روزرسانی OWP هیچ مجوز Git یا Deployment تازه‌ای ایجاد نمی‌کند.

اگر Tag هنوز ایجاد نشده است، از SHA دقیق Commit استفاده کن. مسیر main همیشه جایگزین نسخه ثابت نیست.
